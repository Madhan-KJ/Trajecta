# Trajecta

Routing optimization code, scenario datasets, benchmark inputs, and result artifacts.

The synthetic scenario data uses structured assumptions, not operational data. Each candidate is a complete multi-route plan with four route groups; reported cost, distance, penalty, and on-time metrics are full-plan totals/percentages. The seven fleet entries are vehicle types, not an inventory count; assignment selects distinct types for the four groups. Solomon benchmark runs use published reference route warm starts; Cordeau runs use nearest-depot decomposition and are not independent full-Trajecta evaluations.

## Synthetic experiment

The synthetic instance uses 30 orders and the 18 configured city coordinates. The distance matrix is city-to-city Haversine distance (Earth radius 6,371 km) multiplied by `road_distance_factor`; order coordinates receive uniform jitter around their assigned city. The generated 18x18 matrix is saved to `datasets/city_distance_matrix.csv`.

Each seed evaluates eight splits (EDD, arrival, latitude, travel distance, longitude, latitude-longitude, penalty risk, and DBSCAN) with seven route heuristics, producing 56 candidates. DBSCAN uses the configured kilometre radius and minimum sample count; noise points remain separate before clusters are balanced into route groups. `results/candidate_routes.csv` contains candidate aggregates, while `results/candidate_route_details.csv` contains each candidate's route groups, vehicle, order sequence, city sequence, and route metrics.

On-time means an order's service completion is at or before its due time, after waiting until its arrival/release time. The reported paper metric is the mean and sample standard deviation of seed-level percentages. Service time uses `t_base + alpha*weight + beta*volume + gamma*(fragile + cooling) + delta*skill`, with one reproducible normal skill draw per order and seed. Cost assumptions, including fuel, packaging, cooling, flat class-based per-route tolls, and EV energy consumption and tariff, are in `assumptions.json`; they are synthetic assumptions, not measured tariffs. Infrastructure restrictions are generated by synthetic city-index rules; they are not sourced road data. `window_hours` is not used and is not part of the generator.

Two OR-Tools Guided Local Search comparators are produced: a simplified distance-plus-lateness objective and a seven-factor objective. Neither is Gurobi or an exact solve. Both have a time limit and the second uses a static traffic approximation; 3D packing is checked post-solve, and feasibility failures are retained. Compare full-model costs only on the shared feasible subset and report both the feasible count and all-run count. The ablation runner reports each disabled-feature plan after full-model rescoring. Scalability runtimes are recorded per algorithm.

## Setup

```powershell
python -m pip install -r requirements.txt
python recreate.py
python revision_outputs.py
python download_benchmarks.py
python run_benchmarks.py
```

The first command regenerates the synthetic datasets and experiments, including the ten-seed main run, ablations, scalability, varied scenarios, exact seven-order gaps, and per-candidate tables. The second reads generated CSV/JSON data and writes `results/summary.md`, `results/claims_ledger.md`, `results/paper_changes.md`, and figures under `results/figures/`. Benchmark commands remain separate because their warm-start/depot-decomposition protocol differs. Generated artifacts and their assumptions are in `results/` and `datasets/`.
